# GoldItem recovery

The current MainPanel export's GoldItem subtree is recovered as a reusable GoldItem prefab. It preserves eight transforms, the native Button, source background/icon sprites, TMP settings and the one-second linear Yoyo hint movement to local (0,-90,0). The original parent-relative coordinates are retained; the validation host places the prefab under the actual MainPanel Top. The production MainPanel has not yet embedded it because its full Top initialization and country/reward providers are still pending.

GoldHelp.Start (0x9C40F0), SetGold (0x9C41DC) and GetGoldSprite (0x9C421C) are represented by OriginalGoldImage: a supplied current-country provider, the original GoldCode aliases, Resources sprite path Atlas/Golds/{code}{numeric type}, sprite assignment and SetNativeSize. All nine type-1 sprite assets use the previously imported source textures. The cloned gain icon receives the same live country provider before its Start. No country detection or server configuration is invented. Label 185 participates in the original table localization pass; its English runtime value is Cash, replacing the prefab's placeholder Draw.

GoldItem.Init (0x9DB110) replaces the Button listener, sets ColorTint, hides the hint and refreshes hint content. The original AddLSSListener call explicitly disables its press tween, so no OriginalButtonFeedback component is added. Init does not refresh the amount. Refresh (0x9DB4BC) calls RefreshLssGold(false,0): it writes the formatted current Gold only. RefreshHint (0x9DB210) reads the third reward record, hides after Stage2RealLevel, writes the state description with LF replaced by a space, then requests TX_JD and level-label refreshes when a main host is present. It does not change red color tags. ShowGoldHintText (0x9DC51C) explicitly shows at/below Stage2RealLevel and hides above it; RefreshHint does not implicitly show an earlier-stage hint.

The animated RefreshLssGold branch (0x9DB4C8) refreshes the hint immediately, then waits 0.6 scaled seconds and scales the owner toward 1.15 over 0.06 seconds with OutSine, 12 Yoyo loops. It captures its starting scale after the delay and resets to one on completion. Each call retains its own added-gold value and does not kill earlier pulses.

OnPlay (0x9DC780) copies the configured icon and amount label once, under their respective original parents, with local X offsets +140/+50 and Z zero. Both copies use scale 0.7; the label becomes + followed by formatted added gold. Local Y moves linearly to absolute 80 over two seconds while color approaches white/zero alpha with InCubic. Fade completion destroys both copies (0x9DCCB0). Parameters are serialized in OriginalGoldItem.asset. Copies are made once per reward presentation, not every frame or pulse loop; no static UI hierarchy or font style is assembled in code. Per-frame tracks reuse list capacity. The component itself neither changes the wallet nor saves it.

ClickCallback (0x9DC63C) requests reward information and its response callback (0x9DCDB4) opens panel ID 18. The implementation exposes this request boundary without implementing the excluded SDK/server request. Standard Button clicks respect the host click gate; request comes before click audio, and the panel waits for the supplied completion callback. Tests never contact a service, grant funds or publish a transaction.

Validation: all 28 Unity regression groups pass, including source resources, no missing scripts, country aliases, Japanese label localization, hint boundaries, refresh scope, listener replacement, blocked clicks, deferred panel routing, pulse timing and gain copies. Real Play connects the restored banner to the actual GoldItem destination, ShowGoldHintText and TX_JD.Show, exercises a GraphicRaycaster/Button click, and verifies pause/resume and fade cleanup. The latest 480x854 captures Library/ValidationCaptures/gold-item.png and gold-item-gain.png were visually inspected; the first capture is taken before changing the wallet fixture. Test PlayerPrefs were restored.

**Remaining scope:** production Top initialization, country/reward providers, panel 18 and later guides, complete startup/lifecycle routing, AB/GM and original-device comparison. The Play host uses isolated synthetic reward data and a request callback probe. Whole-owner deactivation during an active gain pulse has not been matched to the original global tween scheduler; the existing test covers scaled pause while active. The current target captures do not establish original-device or Android/iOS equivalence. SDK treatment is unchanged.
