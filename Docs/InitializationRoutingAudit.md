# Initialization lifecycle routing

OriginalGameScene.BindInitialization supplies the main-panel object provider and the restored post-wait continuation. BeginInitialization now schedules that continuation independently of its board rebuild queue. Each invocation captures its continuation and first-entry flag; restart and failure-restart preserve the original showBanner=true, firstInit=false defaults. The provider remains live inside the original Unity-object WaitUntil predicate. No coroutine is cancelled by another restart or lifecycle rebinding.

Source: InitLevel 0x9E8174, successful initialization callback 0x9FF7CC, main-panel predicate 0x9FFF64, delayed continuation 0x9FFC1C/0x9FFD10. Existing SDK treatment is unchanged. The unbound local startup keeps its existing behavior; this is common runtime behavior, with no Editor-only completion or synthesized reward reply.

The unlock Play fixture now binds the runtime lifecycle and calls actual RestartLevel for each of the four variants. It no longer directly opens the eligible panel. After board rebuilding, WaitUntil and the serialized 1.5-second delay, OriginalInitializationContinuation reaches the supplied initialization consumer and the actual scene-configured unlock host. The fixture checks native restart flags and exactly one continuation per restart, then exercises the real Button, target banner, close animation and delayed queue. It explicitly supplies a nonempty ComeOnGold fixture value to cover the native lazy branch without introducing a server document, restoring it at continuation entry. The negative eligibility check still directly probes the host.

This narrows the integration gap but does not complete production startup. The initialization event consumer in this fixture forwards to unlock; full OriginalInitializationFlow, all guide consumers, full main-panel binding and production entry remain outstanding. No claim of complete lifecycle parity is made.
