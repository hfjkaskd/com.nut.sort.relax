# Failure panel sparkle resources and color loops

Five FailureSparkle prefab variants preserve the source FailPanel Image (1) through Image (5) objects, including Image configuration, sprite, and RectTransform. A source/target comparison verified all five RectTransform blocks match except standalone parent/root-order normalization. The original star sprite/texture dependency was imported and the current target texture inspected. These are component resources for later full-panel composition, not a replacement failure screen.

The authoritative enum in dump.cs identifies animationType 6 as Color (Fade is 7). Each source component uses Linear, one-second infinite Yoyo, normal scaled update and endValueColor (1,1,1,0.627451). OriginalLoopColor restores full RGBA interpolation, lazy first-update capture, repeated cycles and the scene-global animation driver so hiding/disabling the image does not stop its track. It allocates no per-frame objects and changes no hierarchy at runtime. Source CoinTip animationType 10 is PunchRotation, not ShakeRotation; that separate dependency is still pending.

56 regression PASS markers in Library/unity-failure-sparkle-validation.log; no compiler errors or exceptions in the final run, preference fixture restored with backup absent. Tests load all five prefab variants, resolve their actual sprite, verify lazy capture, zero delta, linear/Yoyo phases, multi-loop steps, RGBA interpolation, inactive/disabled global dispatch and destroyed target pruning. Edit-mode tests explicitly register the animation because runtime Awake is not invoked by this fixture. During development, an incorrect fade-only interpretation was corrected against the source enum before this commit; the final assets/code use Color.

Full panel rendering and device comparison have not been performed for these resources. The complete FailPanel, CoinTip punch rotation, Button/controller/audio binding and normal startup routing remain pending. SDK treatment is unchanged; whole-game 1:1 completion is not claimed.
