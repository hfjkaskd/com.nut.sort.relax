# Target reward banner recovery

The current typed MainPanel export's TargetReward subtree is restored inside the production MainPanel prefab: five transforms, two source sprites, two TMP labels, original anchors, dimensions, font materials and autosizing. UGUI/TMP components use the official Unity package scripts. Startup performs the original Init reset and exposes the component for the pending initialization host. No runtime-created static UI or serialized UnityEvent calls were added.

Behavior sources are TargetRewardBanner.Init 0x9DE7BC, Show 0x9E0D18, RefreshTip 0x9E0E70, RefreshSubTip 0x9E119C, entry callback 0x9E1474, and movement callback 0x9E16B8. Parameters live in OriginalTargetReward.asset and the existing original panel settings. Init sets local position (-2000,0,0) and scale one. Show refreshes both text fields before resetting and starting a 0.5-second local-X OutBack entry. There is no first-level bypass.

At entry completion the original captures the top GoldItem's world position. It registers a 1-second-delayed, 0.3-second linear world movement, then a separate linear scale-to-0.2 track with the same delay/duration. Each track samples its start only when its delay has elapsed. Completion invokes the optional caller callback, GoldItem.ShowGoldHintText, TX_JD.Show, then Init, in that order.

The native TweenManager update at 0xA3C62C snapshots the active range and visits it in registration order. Tracks created by a completion callback first advance on the next update; entry overshoot time is not transferred to them. The separately registered scale track writes after the move callback's Init reset, so normal completion leaves an offscreen banner at scale 0.2 until its next Init. The authored native motion list preserves this order, overlapping Show calls, scaled time and delayed start capture. It reuses list capacity, stores tracks as values and does no per-frame Find, GetComponent, string formatting or delegate creation. Raw native listings remain local.

RefreshTip consumes OriginalRewardProgress. Stage four uses original text 20 with target currency, instead of the general stage description. Other stages replace existing numeric color-opening tags with yellow; the rest of the text remains intact. The regex's single backslashes were checked in the original metadata bytes, rather than copied from an escaped dumper rendering. At stage seven the first refresh writes IsCompleteSignIn and then requests a save, after the text is assigned. The intervening SDK telemetry call is excluded. Subsequent refreshes do not repeat that save.

RefreshSubTip hides its parent without rewriting text when TotalRound is nonpositive. Otherwise it sets parent visibility from Round > 1 and still writes text 150 when Round is one. Arguments are ShowLevel and Round/TotalRound. No rounding or zero-round placeholder was invented.

Validation: all 26 Unity regression groups pass. The added group checks the restored hierarchy/resources/fonts, source text, stage-four override, one-time sign-in save request, round visibility, delayed start/destination capture, OutBack overshoot, world-space movement, callback/reset/scale ordering, repeated Show calls, and null optional callbacks. A real Play run on the current MainPanel canvas also passes entry/hold, timeScale pause/resume, completion order, reset and no first-level save. The current 480x854 capture at Library/ValidationCaptures/target-reward.png was visually inspected: source purple background, yellow first line and white second line render without missing/magenta assets. Test PlayerPrefs were restored.
