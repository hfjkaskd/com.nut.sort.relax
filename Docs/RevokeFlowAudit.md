# Core revoke manager dispatch

OriginalRevokeFlow restores LuoSiSortMgr.Revoke (0x9FE578) using the existing OriginalMoveRecord history. Empty history returns immediately, without a deadlock check. Otherwise it selects the last record and invokes its revoke operation. A null last record fails. A true result reacquires the current history, calls List.Remove(record), and refreshes only type 2 button state. It does not pop the last index: if duplicate references exist, the first matching reference is removed. A false result retains the record and skips that gray refresh. Both nonempty result paths then evaluate IsCannotMove and invoke Fail when true. Exceptions stop subsequent steps. This manager method itself does not save or consume inventory.

The existing outer OtherItem callback is intentionally separate: it invokes the void manager Revoke and then submits the -1 item delta. Consequently, a record returning false still leads to the outer inventory consumption and save; throwing an exception does not. The restored dispatch preserves this source behavior instead of treating rejection as a transaction rollback.
