# Coin progress and number formatting

Recovered from the current ARM64 TXMgr.GetCoinTXStage (0x9C1420), GetCoinTXStateDes (0x9C1598), get_IsShowCoin (0x9C0874), UILSSUtil.CoinFormat (0x9BF578), and StringUtil.ToDouble (0x9BBFA8). No older captures or unrelated-game assets were used. The native description jump table resolves stages 4/5/6/7 to the shortfall/daily/coin-login/rank branches respectively.

OriginalCoinProgress reads bear_zs_list[index], independently of the cash bear_list. Coin visibility is saved IsShowCoin OR actual Level > 4; this query does not require a reward document. Stage queries require the document and indexed row. They compare the double Coin balance against caliper_psi parsed as float: shortfall is stage 4; otherwise LoginDayCoin >= caliper_logs is stage 7, otherwise TodayPassLevelCount >= cal_cfg is stage 6, else stage 5. Cash LoginDay and cash guide flags do not participate.

Descriptions always use coin row zero. Stage 4 uses text 9 with two cash-formatted arguments: (float)(ToDouble(caliper_psi) - Coin) / ToFloat(bear_rates), then ToFloat(psi_value). This deliberately preserves the distinct double parsing for the difference and conversion to float before division. There is no zero-rate fallback or cash-guide text-24 replacement. Stages 5/6/7 use text 10/11/12 with daily, coin-login and user-rank differences; differences are not clamped. All queries leave the opaque server document unchanged. Missing documents/rows are not silently replaced with fabricated data.

OriginalGoldFormatter.FormatCoin shares that formatter instance's culture cache with Format. A cash call with an explicit country resets the cache used by both methods. Coin first initializes culture from the current-country provider only when uncached, then reads the live country again for integer truncation in ja-JP, id-ID and ur-PK. It uses double F2 with no grouping/symbol, removes only the three recognized zero-decimal suffixes, and retains the source catch/log plus current-culture F2 fallback. Production cash and coin consumers must receive the same formatter instance to preserve the original UILSSUtil shared cache.

Validation adds native boundary cases for the independent login counter, equality and priority, indexed targets, missing data, NaN, float threshold rounding versus double shortfall parsing, zero conversion rate, unchanged JSON and cross-method culture caching.
