# Native UI animation dispatch

The existing startup object in LuoSiSortGame now owns OriginalUIAnimationDriver. It advances registered animation owners from one scaled Unity Update. No runtime UI hierarchy, editor fallback or third-party assembly is added. This addresses the previously documented discrepancy where GoldItem, CoinItem, TargetReward and Get-marker PunchRotation stopped while their GameObject or component was disabled.

The source TweenManager.Update (0xA3C62C) snapshots its active range and dispatches normal-update tweens independently of target visibility; source DOTweenAnimation does not unregister on OnDisable. The native driver snapshots its registration range too. Registrations appended by a callback wait until its next update. Removal tombstones an entry so removing a later owner does not shift the current iteration; compaction runs afterward. Destroyed Unity owners are skipped. Runtime registration state resets at subsystem initialization. The scene must contain exactly one driver.

GoldItem, CoinItem and TargetReward register when a presentation starts, retain the existing local track/callback ordering and unregister when no finite work remains. Each caches its delegate. OnDestroy cancels registration; OnDisable does not. Thus hidden gain copies still appear after the original delay, finish fading and are destroyed on schedule; hidden banner callbacks and final scale/reset order still run. LoopPosition, LoopRotation and RecordPunchRotation register in Awake and unregister on destruction. HiddenLevel's current-dot blink registers when selected. Loops remain scaled and now write inactive target transforms/colors too.

The registry starts with capacity 32, reuses storage and performs no per-frame delegate creation, Find, LINQ or hierarchy search. Only currently registered owners are visited. Finite presentation owners leave the list after completion; permanent source loops remain until their owner is destroyed.

Validation covers snapshot insertion, removal of a later owner during a callback, hidden and disabled targets, zero delta and destroyed-owner pruning. Real Play uses the actual scene driver and restored prefabs with isolated synthetic reward data. It hides cash and the banner, disables the coin component, verifies delayed gain copies still start, pauses scaled time, then verifies completion, clone cleanup, banner callback/final-scale order and reactivation. Hidden hint movement, glow rotation and Get-marker PunchRotation are checked for motion and pause. Destruction during queued presentations must suppress later callbacks. Test preferences are preserved/restored.

Scope remains narrower than a full DOTween reimplementation: the driver registers existing component track groups, not every individual original tween. Cross-component interleaving of newly added tracks within already registered groups, source safe-mode exception handling, scene-persistent tweens and every link/kill interaction are not yet established. Existing original per-component order tests still apply. Full production Top, other panels/lifecycle, AB/GM and device parity remain unfinished. SDK behavior is unchanged. No new visual assets were changed or old screenshots used in this round.
Verified with Unity 2022.3.62f3: 32 regression PASS markers and NUT_UI_ANIMATION_PLAY_VALIDATION_PASS. No compilation/validation exceptions; preference backup absent after restoration. Local evidence: reconstruction-nut/logs/unity-ui-animation-validation.log and unity-ui-animation-play.log in the reverse-source workspace.
