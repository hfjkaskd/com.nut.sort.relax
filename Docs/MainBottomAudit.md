# MainPanel Bottom assembly and dispatch

MainPanelBottom.prefab restores the entire current source Bottom subtree: 20 objects, 95 serialized blocks, five visual children in the original order Revoke, Exchange, AddTile, SettingBg, ReplayBg. All 20 RectTransform blocks match the typed source after normalizing the standalone root parent/order. The serialized OtherItems list deliberately has a different order: AddScrew, Revoke, Exchange. Existing tool prefabs/controllers and official Button/TMP/Image components are reused; the missing settings sprite was recovered from the current export. Button feedback is configured in the prefab, not dynamically added at runtime.

OriginalMainBottomView restores Init 0x9DE5B4: bind Setting, then Replay, then initialize each tool in list order. It does not refresh quantities. SettingCallback 0x9DF54C routes panel 5; ReplayCallback 0x9DF628 routes panel 17. The shared listener path gates the click before routing and plays sound afterward. SDK vibration remains excluded.

Refresh 0x9DE994 runs each item's quantity refresh followed immediately by its gray refresh before advancing to the next item. RefreshOtherItem 0x9DF0A8 and RefreshOtherItemButtonState 0x9DF200 act on only the first matching type, independently. Missing types in these two methods are silent. GetOtherItem 0x9DF358 also returns the first match; a miss logs the source diagnostic and returns null. Diagnostic names are explicit stable mappings instead of enum.ToString or reflection.

All tool controllers and displays receive the same live user, history/level providers, core action callbacks, item-manager delta callback, exchange-state callback, acquisition/pop-tip routing, click gate and sound. The Bottom binder does not implement fake services or mutate inventory outside the recovered controller behavior.

Validation: 47 complete Unity regression PASS markers. The integrated test checks the actual full prefab, visual and serialized-list orders, no missing scripts/dragged events, repeated initialization, settings/replay routes, paired refresh order through observable provider callbacks, independent local updates, missing-type no-op and duplicate first-match behavior. Actual Play replaces the partial Bottom in the real scene, binds before use, invokes settings/replay buttons, and captures gray and active states. Library/ValidationCaptures/main-bottom-gray-play.png and main-bottom-active-play.png were visually inspected; settings icon, replay icon and three tools render at original positions. Fixture inventory is not persisted; the preference backup is restored and absent.

Logs: Library/unity-main-bottom-validation.log and Library/unity-main-bottom-play-validation.log. The full regression log contains a Unity Android deployment-target scan process-exited exception during editor platform initialization; all regression checks subsequently passed. The Play fixture passed without a validation exception. This does not verify device compatibility.

Normal startup still uses the prior partial MainPanel. Full MainPanel lifecycle/provider binding, settings/acquisition/pop-tip panel functionality, core tool execution and inventory persistence, remaining lifecycle branches and country AB/GM switching remain incomplete. Current tests validate routing and composition using explicit fixtures, not complete gameplay actions or 1:1 lifecycle parity. SDK treatment is unchanged.
