# Live board revoke manager integration

OriginalLevelView.Revoke now composes the source manager flow with the actual live operation history, record-level native board reversal, and existing stateful deadlock rules. MoveHistoryCount exposes the live history count for tool displays/controllers without allocating or copying snapshots. The caller supplies Bottom gray refresh and the failure lifecycle action. Source history removal precedes gray refresh; deadlock checking follows record handling even after rejection. Inventory mutation and saving remain outside this manager operation, owned by the existing item manager.

The integration validation instantiates the actual Game/Level and MainPanelBottom prefabs, completes a forward move, clicks the standard Revoke Button and follows controller -> live board manager -> record reverse -> history removal -> gray refresh -> ItemManager consumption -> OriginalUserStore -> Bottom refresh -> audio. It verifies that board data and empty history are saved while reverse animation is pending. The stored LevelInfo is loaded into a second actual level prefab to prove the undo persists as a playable board. Landing releases the original target independently. A subsequent Button click sees empty live history, requests the existing tip action, and skips consumption/save. The preference adapter is memory-backed for test isolation; production serializer/store code is used.

Validation: 52 regression PASS markers in Library/unity-board-revoke-validation.log; no compiler errors or exceptions found, preference fixture restored with backup absent. This batch integration checks real prefab behavior and persistence, not rendered/device visual equivalence. No visual resources changed.

Further source inspection confirms Fail (0x9FC800) guards IsFail, sets it immediately, then schedules a three-second callback; callback 0xA00218 requests panel 10 with empty arguments. That failure presentation dependency remains unimplemented here. The new manager method is available for production wiring, but normal startup still uses the partial MainPanel and has not been switched to the fully bound UI. Other tools, failure panel/lifecycle, currency owners and remaining country AB/GM work remain incomplete. SDK treatment stays unchanged.
