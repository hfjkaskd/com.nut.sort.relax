# Withdrawal ProgressTip punch rotation

The TXPanel source ProgressTip animation specifies duration 1, punch (0,0,10), vibrato 10, elasticity 1, infinite loops and loopType 1 (Yoyo). Existing FailureCoinTip uses the already restored OriginalPunchRotation with a closed Incremental cycle. The final implementation preserves that component, its original script GUID and default behavior, and adds a serialized yoyo flag enabled only in the withdrawal effect configuration.

Rechecked native DOTween.Punch 0xa0eb1c: segment count max(2, trunc(vibrato*duration)), increasing segment weights normalized to duration, alternating linearly decaying offsets with final zero. The withdrawal offsets are 10,-9,8,-7,6,-5,4,-3,2,0 and segment durations approximately (i+1)/55 seconds. Existing OriginalPunchPath already implements this and is reused. SpecialPluginsUtils.SetPunch 0xa33e60 forces ease 6 (OutQuad) at startup despite serialized easeType 1; each segment uses its own OutQuad interpolation as confirmed by Vector3ArrayPlugin.EvaluateAndApply 0xa29b38. The getter reads localEulerAngles (0xa2202c), and the setter converts Euler angles to localRotation (0xa22048).

Yoyo playback reflects the existing elapsed-time position in a two-period cycle. Rotation is based on the startup angle rather than accumulating offsets; existing global animation-driver ownership keeps hidden/disabled targets advancing. Path generation is once per track and per-frame work is a small cached segment scan with no allocations. No additional plugin or assembly is added.

Validation uses the configured effect prefab and verifies ten endpoints/time weights, the first half-segment reaching 75% rather than linear 50%, transition from +10 to -9, lazy nonzero startup angle capture, full forward/reverse return and multi-cycle phase. Existing FailureCoinTip tests also pass, including its original Incremental loop and inactive-target global playback. Earlier iterations exposed an edit-mode Awake assumption and an existing-component identity collision; both were removed by reusing the original component and GUID rather than replacing it.

Final verification: full Unity 2022.3.62f3 regression passed 122 markers in Library/withdrawal-punch-validation-3.log, including NUT_WITHDRAWAL_PUNCH_VALIDATION_PASS, existing NUT_PUNCH_ROTATION_VALIDATION_PASS and final NUT_CONTENT_VALIDATION_PASS. No compiler errors or exception entries in the successful log. Preference backup removed after restoration; launched Unity process exited. Existing pooled-object reparent shutdown warnings remain.

Full TXPanel ProgressTip binding, full-view Play capture and production host remain pending. This configured effect prefab is not the complete TXPanel. No whole-game or screenshot parity claim is made; SDK handling is unchanged.
