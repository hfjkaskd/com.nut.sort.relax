# PMDSimple restoration

Recovered Init 0x9b8238, Update 0x9b9b94 and SetText 0x9b8d90. Init stores the captured level, resets local position and sets root active from a fresh PMD selection. It starts the controller even when hidden. First initialization resets the embedded item y to zero, creates a list containing it, and clones it twice under ScrollView with names 2 and 3. After each clone the source item is moved, so final list-order y positions are -240, 0, -120. Each row independently selects current PMD data and calls the already restored PMDItem.Init; null selection leaves its text unchanged. Repeat Init retains rows, positions and text, updates captured level/visibility and resets the hold.

Update subtracts the full Time.deltaTime from the 1.5-second hold and returns when the result is >=0. Otherwise every row moves by deltaTime*150. At y>=120 it wraps directly to -240, discarding overshoot, resets the hold and refreshes that row. It keeps iterating after a wrap. Constants are serialized in the prefab. Normal MonoBehaviour.Update retains Unity active/enabled scheduling; there is no hidden-view global animation driver. Only two clones and one list are allocated on first initialization; the three-row movement loop allocates nothing. Text selection/formatting occurs only on initialization or wrap.

Recovered PMDSimple prefab preserves eight initial GameObjects and all 22 non-script blocks exactly (32 total blocks). Other UI/TMP component blocks differ only by official script references. Embedded PMDItem uses the existing OriginalMarqueeItemView text/icon/delayed-width behavior. The original pmd_bg sprite and texture dependency are restored. No static UI layout is created in runtime code.

Validation composes actual PlayerInfo -> actual PMDSimple -> three actual PMDItem views using explicitly supplied fixture selection, time and user data. It checks source-after-clone placement, four initial selection reads, the exact zero-hold boundary, full crossing-frame delta, wrapping without overshoot, continued iteration, repeat Init reuse and absent-selection hiding. Clock/data transport and complete TXPanel production ownership remain pending. This is not a whole-game or screenshot parity claim; SDK handling is unchanged.

No compiler errors or exception entries. Preference fixture restored and backup removed; launched Unity process exited. Existing shutdown pooled-object reparent warnings remain.
