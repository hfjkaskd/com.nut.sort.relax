# Item manager inventory mutation

OriginalItemManager restores ItemMgr.AddLssItem (0x9F5F98). The native jump table at 0x2017920 was decoded and verified: types 0/1 route to gold/coin, 2/3/4 update RevokeCount/ExchangeCount/AddScrewCount. Unknown signed or unsigned-out-of-range types do nothing; null item fails. Tool counts use unchecked integer addition, without zero clamping. Every recognized tool mutation calls SaveData first, even for zero quantity, and only then optionally refreshes the whole Bottom. The refresh flag never suppresses saving. Failed save leaves the already-mutated live user and prevents refresh, matching source ordering.

Gold uses ItemInfo.CurrentCount with SetGold flags true,true; coin uses DoubleCurrentCount with SetCoin flag true. These branches return immediately to the currency owner and ignore the item refresh flag. The item manager does not duplicate currency persistence or attempt to implement excluded SDK logic.

OriginalItemInfo retains original fields. IntCount (0x9F61E0) selects CountInt or MoreCountInt based on IsMore; those getters (0x9F8DF8/0x9F8ED4) round midpoint values to even. Explicit conversion preserves source ARM64 behavior for finite overflow and nonfinite values, including the native special case positive infinity returning Int32.MinValue. This behavior is shared by Editor and device; no Editor fallback or reflection is used. The remaining ItemInfo projections and item image/fly APIs are outside this checkpoint.
