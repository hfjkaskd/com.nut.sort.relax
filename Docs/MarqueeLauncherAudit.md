# Marquee launcher recovery

OriginalMarqueeLauncher restores PMDBullet.Init (0x9B865C), Update (0x9B87F0), StartLaunch (0x9B8904) and the PMDSimple.SetText second selection. PMDBullet.prefab includes the original root and restored PMDItem subtree: four transforms, seventeen serialized objects. Original dimensions/position are retained. Timing and aspect parameters are serialized on the prefab.

Init returns when screen height/width is below 2.1 without clearing earlier state. Otherwise it captures the current level, replaces the pool list with the configured template, and marks it ready/started. Update accumulates scaled delta only from actual level four. Initial delay is five seconds; subsequent attempts alternate Range(6,8) and Range(9,11). Each attempt clears elapsed time rather than carrying overshoot. Failed data lookup still consumes the next interval and attempt parity.

StartLaunch first queries data as a guard, selects the first ready item or clones the configured template, then performs the independent second data query for text initialization. A missing second result retains existing text and still launches. It samples the unused full-height range before the parity-specific lane range, uses the template height for both lanes, sets local position to half container width and sampled Y, and travels linearly to negative half width in Range(12,15) seconds. Completion only sets IsReady=true; it does not hide or destroy the item.

Travel tracks live on the item and register with the existing global UI animation driver. Hiding/disabling the launcher stops its Unity Update spawning while item motion continues. First motion update captures the start X; finite tracks deregister on completion and destroyed targets unregister. The ordinary pool reuses ready items and only grows while all are busy. Repeated Init retains original timer/attempt behavior and replaces its pool list; abnormal repeated reinitialization and cross-component tween interleaving still require broader lifecycle coverage.

38 complete Unity regression PASS markers in reverse-workspace reconstruction-nut/logs/unity-marquee-launcher-validation.log. Cases cover aspect boundary/no-side-effect rejection, level gate, initial and alternating delays, missing first/second queries, preserved random draw order, upper/lower lanes, template reuse and busy growth, captured level versus changed live level, hidden global movement, pause and ready-without-hide completion. No compiler/validation exceptions. The preference backup is absent after restoration.

Remaining: production MainPanelTop binding, main-game-owned width coroutine scheduling, actual Play integration/timing and original-device visual comparison. Deterministic validation manually advances the clocks; it does not prove frame-order parity in the completed game. The source data selector and SDK boundary remain separate; no response or SDK request is fabricated.
