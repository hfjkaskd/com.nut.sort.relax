# Marquee data recovery

Recovered PMDS2CData.Init (0x9F209C), TXRandomValue (0x9F230C), PMDS2CInfo.Value (0x9F2320) and PMDInfo.GetPMDS2CData (0x9F1D4C) from the current ARM64 binary. The typed export confirms wt/lw/hh/IsGold, casShowBt, popCas, zsRat and Pmds2CDatas. OriginalMarqueeData explicitly reads these fields from the kinetic_data object; it does not modify the original JObject or use reflection. Read and Init are separate because PMDS2C.InitLss (0x9F206C) invokes Init only after IsSuccess. No success envelope or response is fabricated.

Init splits casShowBt on underscore, assigns the first parsed float to the minimum and the second to the maximum, marks every popCas object IsGold=true, then replaces Pmds2CDatas with cash items followed by coin items. Item objects are shared between the lists; incoming coin IsGold flags are not forcibly reset. It does not clamp/sort amounts, normalize weights or silently replace missing lists. Extra range segments are ignored; a missing second segment fails after assigning the minimum, matching source order. Currency-range parsing follows the existing original current-culture float parser. Both range properties sample anew on each access using Unity Random.Range.

The selector retains the unusual native condition at 0x9F1EE0-0x9F1EE4: compare sampled value against cumulative weight and RETURN the current row when sample > cumulative. Equality continues, and each iteration updates the selected row before the comparison. With nonnegative rows of weights 2,3,5, samples at/below 2 reach the final row; samples above 2 return the first row. This is deliberately not replaced by conventional weighted selection. Float accumulation, a single Range(0,total) draw, the initial item-zero access and missing/empty failures are preserved. Empty initialized lists draw Range(0,0) before failing item-zero access. Null cached data invokes the supplied missing-data request and returns null immediately, including when the supplied callback populates data synchronously. It retries on every subsequent missing query rather than introducing a new request throttle. The actual SDK/server request remains excluded.

Validation: all 33 Unity regression PASS markers, including NUT_MARQUEE_DATA_VALIDATION_PASS and NUT_CONTENT_VALIDATION_PASS. New cases cover initialization and row aliasing, native selection equality/NaN boundaries, float range arguments and call counts, missing-data callback timing, repeated init, malformed/empty inputs, current-culture parsing and untouched source JSON. The existing preference fixture was restored; backup is absent. Local evidence log: reconstruction-nut/logs/unity-marquee-data-validation.log in the reverse-source workspace. No visual assets changed this round.

Next required presentation evidence already checked: PMDBullet.Init (0x9B865C) returns below screen height/width 2.1 without newly hiding or resetting itself; otherwise it captures actual player level, creates a pool list containing the configured template, marks it ready and starts. Update (0x9B87F0) advances its scaled timer only when started and live actual level >=4. Initial stop time is 5; subsequent periods alternate random 6-8 and 9-11 seconds, resetting the launch counter after the second period. A single update launches at most once and discards excess elapsed time. StartLaunch (0x9B8904) queries data once as a guard, then PMDSimple.SetText (0x9B8D90) queries again. It reuses the first ready item or clones the configured template, uses the level captured at Init for text, alternates lower/upper vertical lanes, and traverses the Rect width linearly over random 12-15 seconds. A preliminary random Y draw is consumed even though the following lane draw replaces its result. Completion only marks the item ready.

Remaining: PMDItem text/name/payment-icon construction, delayed width sizing, original PMDBullet prefab and pooled scrolling, actual success-gated data host, production MainPanelTop, later panels and lifecycle, AB/GM and original-device visual parity. These data rules do not establish a working player-facing marquee. SDK behavior is unchanged.
