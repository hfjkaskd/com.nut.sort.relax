# Withdrawal stage shared lifecycle

OriginalWithdrawalProgressFlow restores the shared TXProgressBasePanel controller for later stage-page composition. It uses IOriginalWithdrawalStageUI, distinct from the existing withdrawal-home progress-display interface. Stage-specific panels, their actual view adapters and production routing are not yet restored by this change.

## Native evidence

InitLssPanel 0x9d1b5c calls the base panel initializer, binds virtual Sure, then binds Close directly to the base close operation. It does not capture a required level argument. Default Sure 0x9cf320 only closes; derived stage behavior remains virtual.

RefreshLssPanel 0x9cef94 creates UserLssInfo if absent. Its constructor 0x9c1f34 is only an Object constructor. If ApplicationTime (offset 0x40) is nonpositive, capture the account before calling LocalTimeSeconds and assign that result to ApplicationTime. Then capture the live account again, call LocalTimeSeconds a second time, add 3 with native unchecked integer behavior and assign AccountSureTime (offset 0x48). Do not reuse the first clock result. A positive existing ApplicationTime skips both reads and both assignments, even when AccountSureTime is absent or invalid.

If the Gold text component exists, format and display live UserLocalData.Gold. Then dispatch virtual RefreshSteps. A missing/destroyed Gold component only skips formatting/assignment. No SaveData operation occurs in this base refresh. Clock and text errors propagate after any earlier mutations rather than applying an invented rollback.

RefreshSteps 0x9cf498 iterates numeric Step children against the live child count. It requires each numeric row lookup, but skips a row when Content or Content/Time does not exist. Rows 1, 2 and 3 respectively use ApplicationTime, AccountSureTime and GoldGetTime (offset 0x50), formatting with the source TimeFormat argument 'g'. Other rows are not assigned. Each field is read when that row is processed, so previous label callbacks can affect the next read. The eventual Unity view adapter must preserve these hierarchy and missing-node rules; no runtime layout is generated by this controller.

The clock, gold formatter and source time formatter are explicit injected dependencies. This controller does not substitute UTC/system time or invent localized timestamp behavior. Current tests use deterministic clocks and observable format delegates; concrete time-source and stage-view composition remains work to do.

## Verification

The first compile detected a new interface name colliding with the existing withdrawal-home interface. Only the new interface was renamed to IOriginalWithdrawalStageUI; existing callers and interfaces were retained. Library/withdrawal-progress-base-validation-2.log is the corrected full regression run: 134 PASS markers, zero C# errors/exceptions, and restored preference backup.

Validation covers base/listener order, virtual Sure and RefreshSteps dispatch, absent account creation, two independent clock reads, existing positive timestamps, nonpositive overwrite of both fields, optional display nodes, first mutation surviving second-clock failure, separately captured account references, unchecked long overflow, live field reads between labels, JSON key projection conventions and text-assignment failure preventing step refresh. No SDK callback or real save is fabricated.

Current source TXProgress0Panel, TXProgress1Panel, TXProgress2Panel and TXProgress3Panel prefabs were located in the typed export. Their stage-specific callbacks, animations and actual view/host integration remain incomplete. No new visual screenshot or production-completion claim is made for this controller-only round. The full 1:1 lifecycle, country/AB branches and startup composition remain unfinished.
