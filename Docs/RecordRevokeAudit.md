# Record-level reverse movement

OriginalRecordRevoke restores OperatorInfo.Revoke (0xA0498C), with NutInfo.Move (0xA0458C) mutation boundaries and completion callback 0xA05260. OriginalLevelView.RevokeRecord connects it to the existing native screw/nut prefab views and their transfer animation. Lookups search the current board by screw Index, in source from/to order. Rejected lookups and busy screws retain source logging and false returns. A selected original-from screw reverts its top group before original-to is locked.

Each iteration takes the highest occupied original-to slot regardless of color or hidden type, assigns the first empty original-from slot, starts its visual transfer, then clears readiness and the source slot. Only the callback associated with descending loop index zero unlocks original-to. Missing target space logs and invokes the callback immediately; missing source nuts log and skip it. Zero count still locks and refreshes both caps. Caps refresh original-from then original-to with no done burst. No hidden reveal, new history record, save or forward done-animation event is introduced. Missing nut views do not synthesize completion callbacks. Stagger indexing reads the live record count as in the source.

Validation: 51 regression PASS markers in Library/unity-record-revoke-validation.log, including the new record validation; no compiler errors or exceptions, and preference backup restored/absent. Tests verify mixed-color/hidden identity, state/visual mutation ordering, stagger callbacks, zero-count lock, cap order, and actual Game/Level prefab forward completion followed by reverse motion and landing in the original slot without a completion event. This is a batch native-prefab motion/state test, not a rendered visual comparison or device test. Invalid-record logging branches are evidence-restored but not separately exercised in this checkpoint.

The existing RevokeFlowAudit describes the preceding manager-only checkpoint; this change supplies its physical-record dependency. Normal startup button/manager/failure-panel binding, other tools, currency owners, remaining player lifecycle and country AB/GM routing remain unfinished. SDK treatment is unchanged. No claim of whole-game 1:1 parity is made.
