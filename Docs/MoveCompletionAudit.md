# Immediate move completion and delayed DoneEvent

Local NutInfo.Move 0xA0458C invokes its first callback after moving NutInfo data and scheduling the visual move. Operator callback 0xA0A9A4 acts only for the last transferred nut. This is not the landing callback or the cap-animation completion callback.

OriginalMoveCompletionFlow restores that path after all transfer animations are scheduled, before source visual refresh and the operation's existing save observer. If the destination is incomplete it checks deadlock immediately. If complete, it increments ScrewDoneCount, LuckyScrewDoneCount and LuckyDrawScrewDoneTimes in that order, unchecked, then captures the original board success result. The level-one seed>=3 success branch hides teaching and pushes the hint before scheduling. Configured delays are one second for ordinary completion and two seconds for success.

The delayed callback retains the destination and captured success. DoneEvent runs first; only captured non-success then checks current deadlock and may fail. Non-success also refreshes screw type objects immediately after scheduling. The callback belongs to the scene's existing scaled-time scheduler, independently of nut landing and cap completion.

OriginalGameScene.BindMoveCompletion composes the real user, board predicate, deadlock rules, scheduler and failure path. Required DoneEvent, teaching, hint and type-refresh consumers remain explicit. There is no fabricated reward, success-panel or server response. SDK analytics remain excluded.

Remaining scope: the actual DoneEvent reward/lucky branches, manager Success flow and full success/reward-panel lifecycle still require reconstruction and production composition. The separate landing path's skip-level DoneEvent branch is also not yet restored. Default startup has not bound the full completion context. These changes restore a missing prerequisite and do not establish full lifecycle parity. Raw native evidence stays local.
