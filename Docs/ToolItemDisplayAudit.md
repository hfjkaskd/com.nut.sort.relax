# Bottom tool item display

Recovered the current original RevokeItem, ExchangeItem and AddScrewItem subtrees: five objects and 22 serialized blocks each. Preserved source positions, images, TMP settings and standard Buttons; source parent is the existing Bottom RectTransform 224502609866597578. Added the missing original item/count/plus assets and reused the recovered gray material. OriginalToolItemDisplay restores OtherItem.Refresh (0x9DEC1C) and RefreshButtonState (0x9DEEF0), without adding click or reward behavior.

Item types are explicit integers: 2 Revoke, 3 Exchange, 4 AddScrew. Positive inventory shows Int32.ToString and Atlas/MainPanel/item_count_bg; zero or negative shows empty text and Atlas/MainPanel/item_add. Sprite assignment is unconditional. Unsupported types leave the display unchanged.

Revoke gray state is hasLevel && historyCount < 1. AddScrew gray state is hasLevel && CurrentLevelAddScrewCount >= ServerConfigData.LSSLSMAC. No level bypasses history/config reads and clears gray. A missing live configuration throws. The missing-field default is 12, stored in prefab configuration: verified ServerConfigData constructor 0x9F28AC loads the two integers (10,12) from native address 0x2017918 into offsets 0x5C/0x60. Explicit JSON field reading preserves case-insensitive last-match behavior and does not mutate the document. Exchange and unsupported types do not refresh gray state.

UILSSUtil.SetGray (0x9BFA80) first resolves its shared GrayMaterial, even on a clear, then assigns that material or null to active Image descendants only. The recovered method uses the same Unity traversal semantics with a reusable list, including dynamic/active-child changes; it leaves TMP materials and Button.interactable unchanged. This is visual feedback, not an invented input gate. Refresh is low-frequency; no per-frame hierarchy scans or new material instances are introduced.

45 complete Unity regression PASS markers cover all three prefabs, counts including negative inventory, history and limit boundaries, native default limit, missing config, active/inactive images, unchanged TMP material and button state. Actual Play mounted the current prefabs in the real MainPanel Bottom and captured both gray and active states. Library/ValidationCaptures/tool-display-gray-play.png and tool-display-active-play.png were visually inspected. Test inventory was not persisted and the preference backup was restored/removed. Logs are Library/unity-tool-display-validation.log and Library/unity-tool-display-play-validation.log. The Play log contains a Unity Android target-scan process-exited exception during editor platform initialization; the validation and rendering then completed successfully, with no game-validation exception. Device behavior is not thereby verified.

Bottom Init/Refresh/SettingCallback/ReplayCallback were inspected: settings routes panel 5, replay routes panel 17, and Bottom.Refresh calls each item's Refresh followed immediately by RefreshButtonState. Those controllers, source click feedback, actual tool consumption/reward branches and full Bottom/MainPanel/normal-startup integration remain pending. These standalone display prefabs are not installed into normal startup with inert tool buttons. SDK treatment is unchanged; this is not a claim of completed 1:1 lifecycle parity.
