# Complete Top prefab and shared binding

MainPanelTop.prefab assembles all eight original children in source order: GM, GoldItem, CoinItem, HideLevel, TX_JD, PMDBullet, Level, PlayerGoldGetHint. It contains 77 objects and 307 serialized blocks. It reuses the current recovered component subtrees and dependencies. All 77 Transform/RectTransform blocks were compared against the current typed source MainPanel; they match exactly after changing the standalone Top root parent to zero. The original child order, sibling metadata, anchors, positions, scales and pivots are retained. No runtime hierarchy creation or dragged events were introduced.

OriginalMainTopView binds every consumer before invoking the existing MainTopFlow. Currency/coin display share the formatter and user; cash, coin and GM share click gating, panel routing and sound; marquee and player hint share the same data selector and country provider. Delayed marquee layout uses the supplied main-game delay owner. Hint scheduling reads the live ServerConfigData; self display reads the live UserLssInfo channel index. The component does not provide fake server responses, hard-code a test country or save/grant test rewards.

Native MainPanelTop.Init (0x9DE464) initializes GM, Gold, Coin, hidden-level template, TX_JD and marquee. Although PlayerGoldGetHint is a Top child and a Top field, this method does not initialize it. MainPanel.InitLssPanel (0x9DE35C) calls base initialization, Top, Bottom, TargetRewardBanner, then PlayerGoldGetHint, and finally binds/hides ExchangeMask. The binder preserves that ownership: Top.Init does not call PlayerHint.Init or Push. MainPanel.RefreshLssPanel (0x9DE90C) refreshes Top and Bottom; it does not reset hints. Production parent orchestration remains to be restored with Bottom and exchange behavior.
