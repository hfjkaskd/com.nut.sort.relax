# CoinItem recovery

Recovered the current MainPanel CoinItem subtree as Resources/Prefabs/Panels/CoinItem: eight transforms and 33 serialized objects, including original parent-relative coordinates, native Button, TMP font/material settings, coin icon, coin hint background and label 185. The hint retains its one-second linear Yoyo movement to local (0,-90,0), represented by OriginalLoopPosition. The source sprite asset is referenced directly by the prefab; validation checks that exact asset rather than the PNG importer's same-name generated sprite.

CoinItem.Init (0x9DA284) replaces the Button listener, sets ColorTint and refreshes the hint. The original call opts out of the press tween. Init does not refresh the number. RefreshHint (0x9DA33C) queries coin row zero: stage >= 5 hides the hint parent and returns without changing its text; earlier stages show the parent and use the coin description with LF replaced by space. Refresh (0x9DA454) refreshes the balance/hint first, then applies IsShowCoin to the entire item. RefreshLssCoin (0x9DA508) always refreshes both balance and hint, including calls without animation; this differs from GoldItem.

The animated branch retains the captured float addition, 0.6 scaled-second delay, 1.15 scale, 0.06-second OutSine legs and 12 Yoyo loops. OnPlay (0x9DAA00) clones the configured icon and amount under their respective original parents, applies X offsets +140/+50, Z=0 and scale 0.7, then formats the addition through CoinFormat. Both copies move to absolute local Y=80 linearly over two seconds and fade toward white/zero alpha with InCubic. Pulse completion (0x9DAEAC) resets the original icon parent, which is the CoinItem root in the source prefab. Fade completion (0x9DAF30) destroys the copies. All source parameters are in a separate OriginalCoinItem configuration asset using the existing native reward-animation settings type. No DOTween assembly or static UI construction is added. Pair creation is once per reward presentation, not per frame or pulse loop; per-frame tracks reuse list capacity.

ClickCallback (0x9DA8B4) waits for the reward information callback and then opens panel 19 (0x9DB034). The standard Button respects the supplied click gate and requests data before playing click audio. The excluded server/SDK request stays a supplied boundary; no service, payout, wallet grant or save is fabricated. Cash and coin formatting receive one OriginalGoldFormatter instance, retaining their source shared culture cache. Label 185 uses the actual localization table, including English Cash.

Regression covers the exact prefab resources and missing scripts, disabled press tween, localized label, init refresh scope, stage-five retained text, refresh-before-owner-hide order, saved visibility, listener replacement, gated/deferred panel routing, delayed gain copies, numeric formatting, OutSine scale and loop completion. The real Play harness places the original coin prefab under the existing MainPanel Top, then checks GraphicRaycaster/Button interaction, request completion, scaled pause/resume and copy cleanup with isolated synthetic reward data. It preserves/restores the existing user preferences.

Remaining: production MainPanelTop embedding and initialization, real country/reward providers, actual panel 19 and downstream flows, region AB/GM and original-device comparison. Whole-owner deactivation during an active reward pulse still pauses this component's Update, unlike the original global tween scheduler; the present pause test only establishes scaled pause while active. This limitation also exists in the preceding GoldItem implementation and needs a common native animation scheduling pass. These isolated component checks do not establish full player lifecycle or Android/iOS visual parity. SDK treatment remains unchanged.
