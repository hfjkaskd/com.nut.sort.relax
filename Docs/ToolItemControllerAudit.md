# OtherItem click routes

OriginalToolItemController restores OtherItem.Init (0x9DEAF0), AddScrewCallback (0x9DF810), RevokeCallback (0x9DF884) and ExchangeCallback (0x9DFC2C). The three existing original tool prefabs now serialize the controller and the already recovered Button feedback component. Listeners are bound in code, ColorTint is selected and repeated Init replaces listeners. Init selects the handler from the current type but does not refresh display. Item type arguments for subsequent consumption/acquisition are read live from the display.

AddScrew directly invokes the core manager's add action, without an extra UI stock/history gate. Revoke checks live RevokeCount first: non-positive inventory opens panel 4 with the current item type and never reads history; positive inventory with no history shows pop-tip 3; positive inventory with history invokes the core revoke action, then ItemMgr.AddLssItem with current type, -1f and refresh=true. The controller does not independently decrement inventory. An exception from revoke prevents the manager delta and subsequent click sound. Exchange with positive inventory calls SetExchangeState(true,0); otherwise it opens panel 4 with current type. Entering exchange does not consume inventory in this callback.

The common listener path follows UILSSUtil.AddLSSListener closure 0x9C04A8: supplied click/mask gate, action, click sound. The existing caller-owned gate represents input eligibility and the short mask; no new global input policy is introduced. Source SDK vibrations and analytics are excluded as requested. Source callback exceptions are not silently swallowed.

46 complete Unity regression PASS markers in Library/unity-tool-controller-validation.log, with no compiler or validation exceptions; preference fixture restored and backup absent. Tests use the actual three prefabs and standard Button.onClick, cover repeated Init, rejection before side effects, zero/negative stock acquisition, no-history tip, operation/delta/audio order, exception short-circuit, exchange without premature consumption and add-screw delegation. Existing display and prefab regressions also pass. This round changes component bindings and existing feedback references; it does not change textures, fonts, coordinates or gray-state graphics.

The core manager implementations, ItemMgr persistence/refresh orchestration, acquisition panel and pop-tip presentation still need production binding, as do full Bottom/MainPanel startup and country AB/GM switching. The click controller is not installed into normal startup with no-op providers. Passing these route tests does not prove real inventory consumption, completed gameplay actions or full 1:1 lifecycle parity.
